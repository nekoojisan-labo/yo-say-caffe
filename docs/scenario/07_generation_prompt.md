# 07 シナリオ生成プロンプト

## 目的

AIを使って、経営シミュレーション + 恋愛シミュレーション用のシナリオを設計・本文作成するためのプロンプト。

小説用プロンプトをそのまま使うのではなく、ゲームイベント形式に落とす。

---

## 1. 全体設計用プロンプト

```text
あなたは、経営シミュレーション + 恋愛シミュレーションゲームのシナリオ設計者です。

以下のゲームについて、いきなり本文を書かず、まずゲーム用シナリオ設計を作成してください。

# ゲーム概要

タイトル：妖精カフェ物語
ジャンル：経営シミュレーション + 恋愛シミュレーション
舞台：祖母から受け継いだ森のカフェ「喫茶フェアリーテイル」

主人公：
祖母の死をきっかけにカフェを継いだ若い女性。
カフェ経営を通して、妖精・エルフ・獣人・王族たちと関係を築いていく。

主なゲーム要素：
- カフェ経営
- 仕入れ
- 売上
- 評判
- 資金
- 幻装レベル
- 恋愛キャラとの好感度
- イベントフラグ
- Bad End / Normal End / Romance End / True End

主要キャラクター：
- シオン：森の守護者。祖母と深い関係があり、主人公を見守る。
- ルシア：妖精王国の王子。王族ルート。
- ローザ：隣の花屋。元冒険者の姐御肌。主人公の救済役。
- ゼフィロス：悪徳金融業者。資金難時に接近する危険な存在。

# 作成してほしいもの

1. ゲーム全体のテーマ
2. メインストーリーの流れ
3. 30日想定のイベント進行表
4. 経営イベントの種類
5. 恋愛イベントの種類
6. 各キャラクターのルート構成
7. Bad End / Normal End / Romance End / True End の条件
8. 使用するフラグ一覧
9. 使用するパラメータ一覧
10. イベント本文を書く前に確認すべき矛盾点

# 注意

- 小説のような一本道ではなく、ゲーム内条件で発生するイベント群として設計すること。
- day、flag、money、reputation、glamor、affection の条件を明確にすること。
- 恋愛イベントは経営シミュレーションから浮かないようにすること。
- 各キャラのルートは、カフェ経営と関係する内容にすること。
- まず設計だけを出し、本文はまだ書かないこと。
```

## 2. イベントマトリクス作成用プロンプト

```text
あなたはゲームシナリオのイベント設計者です。

以下の設計をもとに、30日プロトタイプ用のイベントマトリクスを作成してください。

# 出力形式

| ID | 種別 | 発生日/条件 | タイトル | 登場キャラ | 内容要約 | 変化する値 | 完了フラグ |
|---|---|---|---|---|---|---|---|

# 種別

- main
- tutorial
- management
- romance
- crisis
- rescue
- ending

# 注意

- 1日に重要イベントを詰め込みすぎないこと。
- 各イベントの発生条件に必要なフラグが、前のイベントで必ず立つようにすること。
- 恋愛イベントは、経営やカフェの状況と接続すること。
- Bad End条件と救済イベントの両方を用意すること。
- 30日内で少なくとも1つの成功エンドと1つのBad Endに到達できるようにすること。
```

## 3. キャラルート設計用プロンプト

```text
あなたは恋愛シミュレーションゲームのルート設計者です。

以下のキャラクターについて、経営シミュレーションと連動する恋愛ルートを設計してください。

# キャラクター情報

名前：
役割：
性格：
主人公との関係：
カフェ経営との接点：
抱えている悩み：
ルートのゴール：

# 出力してほしいもの

1. キャラの魅力
2. 主人公との関係変化
3. 経営シミュレーションとの接続
4. 5章構成のルート表
5. 各章の発生条件
6. 各章で変化する好感度・フラグ
7. エンディング条件
8. 会話の口調メモ

# 注意

- 恋愛イベントだけで独立させないこと。
- 必ずカフェ経営、評判、幻装レベル、資金、森の問題のいずれかと関係させること。
- 1章ごとに主人公とキャラの距離感が変化するようにすること。
- キャラの秘密を一度に全部明かさないこと。
```

## 4. イベント本文作成用プロンプト

```text
あなたはゲームシナリオライターです。

以下のイベント設計をもとに、TypeScript の ScenarioChapter[] に変換しやすい形でイベント本文を作成してください。

# イベント設計

ID：
タイトル：
種別：
発生条件：
登場キャラ：
内容要約：
選択肢：
変化する値：
完了フラグ：
次につながるイベント：

# 出力形式

1. イベント概要
2. イベント内の流れ
3. ナレーションと会話
4. 選択肢
5. 各選択肢の効果
6. TypeScript実装用の疑似データ

# 文体ルール

- スマホで読みやすい短さにする。
- ナレーションは説明しすぎない。
- セリフでキャラの個性を出す。
- 選択肢はプレイヤーの価値観が出るものにする。
- 経営イベントでは、数値変化と感情変化をつなげる。
- 恋愛イベントはカフェ経営から浮かせない。
- ゼフィロス関連は、最初は丁寧で親切そうに見せ、徐々に怖さを出す。

# 禁止

- 長い小説本文にしない。
- 設定説明だけの会話にしない。
- すべてのキャラを同じ口調にしない。
- 選択肢の意味をなくさない。
```

## 5. 既存シナリオ整理用プロンプト

```text
あなたはゲームシナリオの構成管理者です。

以下の既存シナリオファイルを読み、重複・矛盾・フラグ揺れ・到達不能イベントを洗い出してください。

# 確認対象

- src/game/scenario.ts
- src/game/scenarios/index.ts
- src/game/scenarios/prologue.ts
- src/game/scenarios/tutorial.ts
- src/game/scenarios/shion/main.ts
- src/game/scenarios/ikemen/lucia.ts
- src/game/scenarios/events/rosa.ts
- src/game/scenarios/events/zephyros.ts
- src/game/scenarios/events/shouran.ts

# 出力してほしいもの

1. 正本として扱うべきファイル
2. 旧版として退避すべきファイル
3. 重複しているイベント
4. 揺れているフラグ名
5. 到達不能の可能性があるイベント
6. 30日プロトタイプに必要な不足イベント
7. 次に修正すべき優先順位

# 注意

- 推測と確認済み事実を分けること。
- 削除が必要な場合は、すぐ消さずに退避案を出すこと。
- 実装前に影響範囲を整理すること。
```
