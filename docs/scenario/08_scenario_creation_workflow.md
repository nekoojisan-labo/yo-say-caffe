# シナリオ制作フロー

このファイルは、新方針でシナリオ本文を作るための実作業手順を定義する。

旧版・試作版のシナリオ展開は参照しない。

この設計では、ゲームを「小説」ではなく、条件で発生するイベント群として作る。

## 基本方針

本作は、以下の3つを同時に進めるゲームである。

1. カフェ経営
2. 恋愛キャラクターとの関係構築
3. 森とカフェを脅かす危機への対処

そのため、イベント本文を書く前に、必ず以下を決める。

- いつ発生するか
- 何を変化させるか
- どのキャラクターの印象を強めるか
- 経営・恋愛・メイン危機のどれに属するか
- 次のイベントやエンディングにどう接続するか

## 制作順

### Phase 1: 30日全体の流れを固定する

参照ファイル:

- `02_game_flow_30day.md`
- `04_event_matrix.md`

まず、Day1〜Day30のどこで何が起こるかを決める。

目安:

| 期間 | 役割 |
|---|---|
| Day1〜3 | 導入・チュートリアル |
| Day4〜7 | 通常経営開始、ローザ・シオン導入 |
| Day8〜14 | ルシア導入、ゼフィロス接近 |
| Day15〜21 | 妨害・資金危機・恋愛ルート分岐 |
| Day22〜28 | 反撃準備・恋愛クライマックス前 |
| Day29〜30 | 決着・エンディング |

### Phase 2: イベント単位に分解する

1イベントは、スマホでも読みやすい短さにする。

目安:

- ナレーション: 1〜3個
- 会話: 5〜15個
- 選択肢: 0〜1個
- 分岐: 最大3つ
- 効果: flag / affection / money / reputation / glamor のいずれか
- 読了時間: 1〜3分

長い小説風の章ではなく、短いゲームイベントとして作る。

### Phase 3: イベント仕様を先に書く

本文を書く前に、`09_event_authoring_template.md` の形式でイベント仕様を作る。

必須項目:

- eventId
- title
- category
- triggerCondition
- purpose
- characters
- summary
- choices
- effects
- next hooks

ここが曖昧なまま本文を書くと、実装時に破綻する。

### Phase 4: 本文を書く

本文は以下の順番で作る。

1. 導入ナレーション
2. キャラクター登場
3. 会話で状況説明
4. 主人公の反応
5. 選択肢または感情の山
6. 効果・フラグ変化
7. 次イベントへの余韻

本文では、ゲーム都合の説明をそのまま語らない。

悪い例:

> 評判が15以上なので、ルシアが来店しました。

良い例:

> その日の午後、いつもより少し背筋の伸びた客が増えていた。噂が、森の奥よりさらに遠くまで届き始めているのかもしれない。

### Phase 5: 実装形式に変換する

最終的には `ScenarioChapter[]` に落とす。

ただし、本文制作段階では TypeScript に直接書き込まない。

先に Markdown でイベント仕様と本文を確定し、その後で実装する。

推奨順:

1. Markdownでイベント本文を作る
2. フラグとIDをレビューする
3. `src/game/scenarios/` 配下にTypeScript化する
4. type-check / build を通す

## 最初に作るべきイベント群

30日プロトタイプでは、まず以下を優先する。

### 1. プロローグ

目的:

- 主人公がカフェを継ぐ理由を提示する
- 祖母の存在を物語の核にする
- シオンとの初接触を描く
- 幻装・照覧・森の特殊性を匂わせる

### 2. Day1〜3 チュートリアル

目的:

- 経営操作を自然に説明する
- シオンを案内役として印象づける
- 経営と幻装レベルの関係を提示する

### 3. Day5 ローザ導入

目的:

- カフェの外部人間関係を広げる
- 救済役を早めに登場させる
- コメディと安心感を入れる

### 4. Day7 シオン第1章

目的:

- シオンを恋愛対象として意識させる
- 祖母との過去を示唆する
- 森の秘密を軽く出す

### 5. Day10〜14 ルシア導入・ゼフィロス接近

目的:

- 恋愛ルートの選択肢を増やす
- 経営の成長を実感させる
- 危機の種を置く

### 6. Day15〜21 妨害・危機

目的:

- 経営シミュレーションの緊張感を出す
- 資金、評判、選択の重みを出す
- ローザ、シオン、ルシアの助け方に差を出す

### 7. Day22〜28 反撃準備

目的:

- プレイヤーの積み上げを回収する
- 恋愛キャラごとの助力を描く
- True End 条件の伏線を出す

### 8. Day29〜30 決着・エンディング

目的:

- 経営成果と恋愛成果を反映する
- Bad / Normal / Romance / True を分岐させる
- カフェの未来を示す

## チェックリスト

イベント本文作成後、以下を確認する。

- イベントの発生条件が明確か
- 旧版展開を無意識に引き継いでいないか
- 経営・恋愛・危機のどれに属するか明確か
- キャラの役割が被っていないか
- 選択肢が意味のある差になっているか
- 効果が強すぎないか
- フラグ名が既存方針と一致しているか
- 次に続く余韻があるか
- 1イベントが長すぎないか

## 禁止事項

- 旧版シナリオの展開を前提にする
- キャラの口調をファイルごとに変える
- フラグ名をその場で増やし続ける
- 1イベントで複数の大事件を処理する
- 経営イベントと恋愛イベントを完全に分離する
- Bad End を理不尽な初見殺しにする
- True End 条件を後出しにする
